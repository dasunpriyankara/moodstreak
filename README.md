# MoodStreak – Habit & Mood Journal (Mobile Hybrid App)

Three-tier hybrid app: **jQuery Mobile + Cordova client → Express/Node HTTPS API → MongoDB Atlas**.


GitHub: [https://github.com/dasunpriyankara/moodstreak](https://github.com/dasunpriyankara/moodstreak)

Live API (Render): [https://moodstreak.onrender.com](https://moodstreak.onrender.com)

```
moodstreak/
├── client/              Cordova project (config.xml, www/ = jQuery Mobile web app)
├── server/              Express API (routers, JWT auth, CORS, HTTPS) + tests
├── docs/                screenshots, test + vulnerability scan output
├── presentation/        MoodStreak.pptx (Part B)
└── render.yaml          Render deployment blueprint
```

## Features
* Sign up / log in / log out (JWT; logout revokes the token server-side)
* Daily mood log (1-5 + note) – **POST / PUT / DELETE**
* Habits with daily check-ins and streaks – **GET / POST / PUT / DELETE**
* Insights: 30-day mood chart, streaks, completion %, "mood booster" (average mood on days a habit was done vs. not)
* Cordova features: daily local-notification reminder, vibration feedback, status bar, offline banner, hardware back button

## API (all under `/api`, everything except signup/login needs `Authorization: Bearer <jwt>`)
| Method | Path | Purpose |
|---|---|---|
| POST | /auth/signup, /auth/login | create account / get token |
| GET | /auth/me | current user |
| POST | /auth/logout | revoke token |
| GET / POST | /habits | list (with streaks) / create |
| PUT / DELETE | /habits/:id | rename / delete |
| POST | /habits/:id/checkins | check in `{date}` (idempotent) |
| DELETE | /habits/:id/checkins/:date | undo check-in |
| GET / POST | /moods | list (`?from&to`) / create |
| PUT / DELETE | /moods/:id | update / delete |
| GET | /stats/summary | streaks, mood series, insights |

## 1. MongoDB Atlas (database)
1. Create a free cluster at <https://cloud.mongodb.com>, create a **database user**, and under *Network Access* allow `0.0.0.0/0` (Render uses changing IPs).
2. *Connect → Drivers* → copy the connection string. Put your db name in it, e.g. `.../moodstreak?retryWrites=true&w=majority`.
3. Collections/indexes are created automatically on first start.

## 2. Run the server locally (HTTPS)
```bash
cd server
npm install
cp .env.example .env          # fill in MONGODB_URI and JWT_SECRET
npm run gen-cert              # self-signed cert for localhost (dev only)
npm start                     # https://localhost:8443
npm test                      # 23 automated API tests (in-memory store, no DB needed)
```
No MongoDB handy? `node scripts/demo-server.js` runs the same API with an in-memory store and seed data
(login `demo@moodstreak.app` / `demo12345`) – useful as a backup for your live demo.

## 3. Deploy the server to Render
1. Push this repo to GitHub (see §5).
2. Render → **New + → Blueprint** → pick the repo (uses `render.yaml`), or create a *Web Service* with root dir `server`, build `npm ci --omit=dev`, start `node server.js`.
3. Set env vars in the dashboard: `MONGODB_URI`, `JWT_SECRET` (auto-generated by the blueprint), `NODE_ENV=production`, `BEHIND_TLS_PROXY=true`.
4. Render terminates TLS and serves `https://<name>.onrender.com`; the app rejects any request that did not arrive over HTTPS.
   (Free instances sleep – open `/health` before your demo to wake it.)

## 4. Build the hybrid app with Cordova
```bash
# prerequisites: Node, JDK 17, Android Studio (SDK + an emulator or a phone with USB debugging)
npm i -g cordova
cd client
# edit www/js/config.js  ->  API_BASE: 'https://<your-service>.onrender.com'
# edit config.xml        ->  <access origin="https://<your-service>.onrender.com" />
npm install
cordova platform add android
cordova plugin add cordova-plugin-statusbar cordova-plugin-network-information cordova-plugin-vibration cordova-plugin-local-notification
cordova run android            # or: cordova build android  (APK in platforms/android/app/build/outputs/apk)
```
Quick browser preview (no Cordova): `cd client && npx http-server www -p 8080`, then add `http://localhost:8080` to the server's `CORS_ORIGINS`.
iOS (Mac only): `cordova platform add ios && cordova run ios`.

## Security notes
* No credentials in code – everything via environment variables (`.env` is git-ignored).
* HTTPS enforced; helmet headers; CORS allow-list; JWT (HS256, 7 d, revocable); bcrypt (12 rounds); input validation (express-validator); rate-limited auth; 10 kb body cap; per-user data scoping.
* See `docs/vulnerability-scan-output.txt` and the slides for the preliminary vulnerability analysis.
